# Route Governance Skill v2.2

> English version. The canonical (Chinese) file is `SKILL.md` — do not edit this one when updating the skill.

Runs route governance on a Web project that has **already been generated by AI**: archaeology scan of existing jumps → **semantic-intent review (understanding what every feature/button on the real page actually means)** → human-confirmed golden baseline route table (with expected targets) → constant freeze + global rewrite → validation and gates. Applies to projects where button A lands on page B, button labels disagree with what they actually do, URLs are hardcoded everywhere, and there is no existing route table.

> **v2.2 additions** (2026-08-13): ① Phase 1.5 "semantic-intent review" — loads the real pages, understands the business meaning of each feature/button, and compares intent against destination (plugging the hole left by pure URL validity checks); ② vision capability calls — screenshots + a vision model to re-verify what buttons actually look like and how they behave; ③ the golden table schema extends with `intent / expected_target / semantic_status`, so "business expectation" becomes part of the truth; ④ Phase 5 changes its visual-validation baseline from "current URL" to "expected target"; ⑤ the Phase 1 scanner extends to the full clickable-element set (button / onclick / toast / SPA view switches).

## When to use (trigger conditions)

- The user reports that a page button or entry jumps to the wrong page, or that **the button label does not match the semantics of where it goes** (e.g. "Save" lands on the landing page);
- An existing project needs a unified routing system (ROUTES constants);
- A new project needs a route gate before development starts;
- The user explicitly says "run route governance".

## Top-level theory rules (do not violate)

1. **Single source of truth** — the only source for internal business-jump URLs is the routes.js/routes.ts constants; hardcoding is forbidden. External links go into the EXTERNAL_ROUTES whitelist.
2. **Bidirectional mapping** — maintain both feature-name→URL and URL→feature-name.
3. **Archaeology ≠ truth** — scan results are only a snapshot of the current state; only the human-confirmed golden table is the truth.
4. **State isolation** — all intermediate artifacts go to disk; nothing depends on conversation context. Context overflow uses a sharding protocol.
5. **Semantic-intent principle** (v2.2) — the golden table records both the "current URL" and the "business expected target" (expected_target); **the semantic layer follows business expectation** — a current URL being valid and reachable does not mean it is semantically correct. Every entry's "label intent" must be compared against its "destination target".

## State container

Create `./route_manage/` at the project root. All intermediate artifacts go to disk; the conversation only carries summaries:

```
route_manage/
├─ 01_raw_scan_routes.json        # Phase 1 route A: raw archaeology scan (script-generated + agent-supplemented)
├─ 01-runtime_scan_routes.json    # Phase 1 route B: runtime collection (Playwright/crawler, or degraded)
├─ 01-dynamic_route_register.json # Phase 1: full dynamic route register
├─ 01.5_semantic_review.md        # Phase 1.5: semantic-intent review report (per page, per entry: label intent / actual target / expected target / verdict)
├─ 02_golden_routes_draft.json    # Phase 2: machine pre-audit first version (before human confirmation)
├─ 02_golden_routes_final.json    # Phase 2: human-confirmed final version (the truth, agent read-only)
├─ 03_diff_report.md              # Scan vs. golden table diff + pre-audit grouping
├─ 04_modify_plan.md              # Rewrite plan
├─ 05_test_result.md              # Validation report
├─ 06_audit_log                   # Audit log (each change: file / before-after snippet / basis)
└─ 07_acceptance_report.md        # Acceptance report
```

## Execution flow (strict order, no phase may be skipped)

### Phase 1: Archaeology scan (two routes reconciled + full element set)

1. **Route A (static)**: run the helper script (see the end of this file) `node scan-routes.js <project root>`, which outputs `01_raw_scan_routes.json`. The script only does a coarse scan (a-href / location / window.open / router / form / iframe / img / fetch candidates + dynamic markers); **the semantic audit is yours to do** — fill in entry_name (the entry's display name), correct entries, and identify missed catches.
2. **Route B (runtime)**: if Playwright or a crawler is available, walk the whole site and collect real jumps; **if no environment exists, degrade** to "manual walkthrough + browser console Network capture", and state the reason for degrading in the summary. When degraded, replace zero-hit spot checks with a full re-check.
3. **Full clickable-element set** (v2.2): Route B collection is not limited to `a[href]` — it also includes `button[onclick]`, any `[onclick]`, SPA view switches (things like `go('view')`), toast placeholders, and form submissions. **These are the raw material for the semantic review** — missing them means missing both the "looks like a link but does nothing when clicked" and "button jumps to the wrong place" classes of problem.
4. **Reconciliation**: in A but not B = dead-code candidate; in B but not A = dynamically generated and missed by the static scan. Take the union. Dead code goes into the defect list for a human delete/keep decision — it is never deleted automatically.
5. **Zero-hit spot check**: list the files with no jumps and sample them to decide whether they are genuinely empty or were missed by the scan.
6. Output a summary: number of scanned files, number of candidates, number hardcoded, number dynamic, number of clickable elements.

### Phase 1.5: Semantic-intent review (the core v2.2 addition)

**Goal**: understand the business meaning of every feature/button on the real pages, and compare intent against destination — fixing the hole found by pure URL validity checking (the URL is valid but semantically wrong, e.g. "Save favorite" jumping to the landing page).

1. **Load the real pages**: start a local server (prefer the project's own serve script) and walk every page (all main pages + representative sub-pages).
2. **Per-element semantic understanding**: for each clickable element, understand its business meaning in page context. Factors include: the full label text (Chinese and English), the section it sits in (navigation / tool page / footer / card), the elements before and after it, the button hierarchy (the shared destination of buttons in the same group), and the page title plus the target page's content.
3. **Visual re-verification (call a vision capability)**:
   - Screenshot key pages with a browser tool (browser/tab.screenshot);
   - Analyze the screenshot with a vision model (your host tool's image-analysis capability, or this repository's `skills/visual-verify/scripts/analyze-image.js`): confirm the button's visual presentation (does it look like something clickable), the real feedback after clicking (jump / toast / no response), and the difference between same-page view switches and full-page navigations. If the vision capability is unavailable, declare the degradation and rely on code context;
   - Vision is for **re-verification and supplementation** — it cannot replace code-layer semantic understanding. If vision is unavailable, declare the degradation and rely on code context.
4. **Intent-vs-target comparison**: classify each entry into one of four kinds:
   - ✅ **Consistent**: label intent and destination target match;
   - ✗ **Mismatch**: the destination exists but is semantically wrong (e.g. "BACK to hub" → landing page instead of the dashboard view);
   - ⚠ **Placeholder**: the target is not implemented (toast('Placeholder'), `#` dead end, alliance placeholder);
   - ⚠ **Dead end**: clicking produces no response at all, or it errors out.
5. **Output** `01.5_semantic_review.md`: list each entry per page with "label intent / actual target / expected target (expected_target) / verdict / notes", formatted like a semantic observation report (a human can see at a glance where things should go).

### Phase 2: Golden baseline table (human confirmation, machine pre-check)

1. Based on the scan plus the semantic review, run a pre-audit and split into three groups: ① high confidence [recommend adopting] ② to be confirmed [human must check] ③ anomalies/errors [human intervention].
2. **Machine pre-check**: self-check the first version of the golden table — no bidirectional-mapping conflicts, URLs are legal, no duplicate mappings (for multilingual projects, split the check per language dimension; the same feature with URLs in several languages is not a conflict). Semantic field completeness (v2.2): every business entry must have intent + expected_target + semantic_status, and a missing one blocks progress.
3. Output `03_diff_report.md` (shown grouped). Spot-check 10% of the high-confidence group; 100% human check for the to-be-confirmed and anomaly groups.
4. **Golden table schema (v2.2)**, one record per entry:
   ```json
   {
     "entry_name": "功能/按钮显示名称",
     "intent": "业务意图（这个按钮应该做什么）",
     "path": "现状 URL（可能为空：SPA 视图/toast/死路）",
     "expected_target": "期望目标（/hub#hub、/report、空=应为死路但需人确认）",
     "group": "nav|page|content|special|semantic",
     "confidence": "high|confirm",
     "semantic_status": "ok|mismatch|placeholder|dead",
     "notes": "语义审查说明"
   }
   ```
5. Output `02_golden_routes_draft.json`, then generate `02_golden_routes_final.json` after human feedback. Output the draft/final diff — **it only takes effect after a human confirms the diff**. Fully dynamic routes do not enter the golden table; they are registered in `01-dynamic_route_register.json`. **The human confirmation list = an intent-vs-target cross-reference table** (with expected targets, like 01.5_semantic_review.md), not a bare URL list — this is what lets a human actually spot semantic mismatches.

### Phase 3: Constant freeze

1. Generate `src/routes.js` / `src/routes.ts` from the golden table: `ROUTES` (forward) + `ROUTE_NAME_BY_PATH` (reverse); external links go into `EXTERNAL_ROUTES`.
2. Semi-dynamic routes use function-style constants like `ROUTES.userDetail(id)` (keep the parameter logic; do not change it on your own).
3. Semantic mismatch entries (semantic_status != ok) **do not enter the constant freeze** — hand them to a human to decide first (change expected_target, remove the entry, or register a placeholder).
4. Write `04_modify_plan.md`. **Do not touch source code yet.**

### Phase 4: Global code rewrite (batched + build gate)

1. Work against the complete list of jump sources (a tags, onclick, window.open, location.href/assign/replace, form action, iframe, image links, menu config, component config items), handling them category by category. "Fix it while you're there" is forbidden.
2. Mechanical replacement uses a codemod script (AST replacement) — you only review the diff. Global string replacement is forbidden.
3. More than 20 files to change → batch them. **After each batch you must build + smoke-test the home page, and only move to the next batch once it passes. On failure, roll that batch back immediately** (git branch / snapshot).
4. Circuit breaker: hitting a jump that is not in the golden table → do not invent a route. Mark it "undefined route" into the defect report and hand it to a human (add to the golden table / remove the entry / change to an external link).
5. Write `06_audit_log` for every change.

### Phase 5: Three-tier validation

1. Code semantic validation (must run): searching the whole project, hardcoded internal business URLs must be zeroed out; every constant reference must be findable in the golden table; no references to undefined constants.
2. **Semantic re-validation (v2.2)**: re-check each semantic mismatch fix item by item — the button's label intent matches its final destination, and placeholder/dead-end items have been handled per the human decision.
3. Visual click validation (toggleable, fallback): local preview + walk every golden-table entry and simulate clicks, **using expected_target (the expected target) as the baseline** when comparing actual jumps — not the current URL. Distinguish real bugs from environment-induced false anomalies. Disable this when the route count is large.
4. Build test: the build must not error.
5. Defects are reported only — never fixed on your own.

### Phase 6: Long-term gate

1. Put the gate rule into the project's AGENTS.md (red line: internal jumps may only reference ROUTES constants) + a mandatory hardcoded-scan self-check before delivery.
2. New feature flow: update the routes constants first, then write the business code.
3. Optional: a git pre-commit hook that scans for hardcoded URLs.

## Circuit breaker rules

Hitting a severe conflict at any phase (one feature with multiple URLs, undefined routes over threshold, constant conflicts) → **stop modifying source code, output a report, and wait for a human decision**. The golden table is read-only for the agent — never alter the truth to suit the code. Until a human decides, automatically "fixing" a semantic mismatch entry is forbidden.

## Acceptance metrics (all must be met for governance to be considered complete)

| Metric | Standard |
|---|---|
| Scan coverage | 100% (scanned ÷ all business source files) |
| Static hardcoded business URLs | 0 (whitelisted external links excepted) |
| Golden table machine self-check | conflicts, duplicate mappings = 0; semantic fields (intent/expected_target/semantic_status) complete |
| Semantic mismatch rate (v2.2) | 0 — every mismatch entry is fixed or has a human decision; every placeholder/dead entry is registered with a recorded human decision |
| Route click pass rate | ≥ 98% (measured against the expected target; exemptions for login-restricted pages must record a reason; an exemption rate over 20% degrades acceptance to a manual walkthrough) |
| Dynamic route registration rate | 100%, no unclassified routes |
| Gate recurrence rate | Sample new code 10 times, hardcoded recurrences = 0 |

## Helper script (embedded, Phase 1 route A)

Write the code below into a temporary file (e.g. `/tmp/scan-routes.js`) and run:

```
node scan-routes.js <project root> [--out <output json path>]
```

- Default output is `<project root>/route_manage/01_raw_scan_routes.json`, with a summary printed to stdout;
- Scans .html/.js/.jsx/.ts/.tsx/.vue/.svelte/.astro/.php, automatically excluding node_modules/.git/dist/build and similar;
- Output fields: entry_type, source_file, line, code_snippet, raw_target_url, is_hardcode_url, dynamic, external, remark;
- Limitation: a coarse candidate scan at the URL-string level. Semantic judgment and missed-catch supplementation are handled by the Phase 1.5 semantic-intent review; `entry_name` must be filled in by a human or the agent.

```js
#!/usr/bin/env node
// scan-routes.js — 路由治理阶段1 A路：静态粗扫候选跳转
// 用法: node scan-routes.js <项目根目录> [--out <输出json路径>]
// 输出: 默认写 <项目根>/route_manage/01_raw_scan_routes.json；stdout 打印汇总
const fs = require("fs");
const path = require("path");

const EXCLUDE_DIRS = new Set([
  "node_modules", ".git", "dist", "build", "out", ".next", ".nuxt",
  "route_manage", ".project-truth", "coverage", ".cache", "public/vendor",
]);
const EXCLUDE_EXT = new Set([".png",".jpg",".jpeg",".gif",".svg",".webp",".ico",
  ".woff",".woff2",".ttf",".eot",".map",".pdf",".zip"]);
const SCAN_EXT = new Set([".html",".htm",".js",".jsx",".ts",".tsx",".vue",".svelte",".astro",".php"]);

// 跳转模式（尽力而为的粗扫；语义判断由执行 Agent 完成）
const PATTERNS = [
  { type: "a-href",       re: /\bhref\s*=\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "location-href",re: /(?:location\.href|window\.location(?:\.href)?)\s*=\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "location-api", re: /(?:location|window\.location)\.(?:assign|replace)\(\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "window-open",  re: /window\.open\(\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "router-push",  re: /(?:router|\$router)\.(?:push|replace|navigate)\(\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "use-navigate", re: /navigate\(\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "link-to",      re: /<Link\s+[^>]*\bto\s*=\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "form-action",  re: /<form\s+[^>]*\baction\s*=\s*(?:"([^"]+)"|'([^']+)')/g },
  { type: "iframe-src",   re: /<iframe\s+[^>]*\bsrc\s*=\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "img-src",      re: /<img\s+[^>]*\bsrc\s*=\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "fetch-api",    re: /fetch\(\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
  { type: "window-location", re: /window\.location\s*=\s*(?:"([^"]+)"|'([^']+)'|`([^`]+)`)/g },
];

function classify(url) {
  const u = (url || "").trim();
  if (!u) return { kind: "empty", external: false, dynamic: false };
  if (u.startsWith("#") || u.startsWith("javascript:") || u.startsWith("mailto:") || u.startsWith("tel:"))
    return { kind: "special", external: false, dynamic: false };
  if (/^[a-z][a-z0-9+.-]*:\/\//i.test(u) || u.startsWith("//"))
    return { kind: "external", external: true, dynamic: false };
  const dynamic = u.includes("${") || u.includes("+");
  return { kind: "internal", external: false, dynamic };
}

function lineOf(content, index) {
  let line = 1;
  for (let i = 0; i < index && i < content.length; i++) if (content.charCodeAt(i) === 10) line++;
  return line;
}

function walk(dir, out) {
  let entries;
  try { entries = fs.readdirSync(dir, { withFileTypes: true }); } catch { return; }
  for (const e of entries) {
    if (EXCLUDE_DIRS.has(e.name)) continue;
    const full = path.join(dir, e.name);
    if (e.isDirectory()) walk(full, out);
    else if (e.isFile() && SCAN_EXT.has(path.extname(e.name).toLowerCase()) && !EXCLUDE_EXT.has(path.extname(e.name).toLowerCase()))
      out.push(full);
  }
}

// 调用型模式：参数可能为拼接表达式，需要检查整个参数
const CALL_TYPES = new Set(["window-open", "location-api", "router-push", "use-navigate", "fetch-api"]);

function scanFile(file, root, results) {
  let content;
  try { content = fs.readFileSync(file, "utf8"); } catch { return; }
  const rel = path.relative(root, file).split(path.sep).join("/");
  for (const { type, re } of PATTERNS) {
    re.lastIndex = 0;
    let m;
    while ((m = re.exec(content)) !== null) {
      let raw = (m[1] || m[2] || m[3] || "").trim();
      let dynamic = false;
      let remarkExtra = "";
      if (CALL_TYPES.has(type)) {
        // 抓整个调用参数，识别拼接表达式（'/' + slug、模板字符串等）
        const after = content.slice(m.index + m[0].length, m.index + m[0].length + 200);
        const paramEnd = after.search(/[);,]/);
        const params = (paramEnd >= 0 ? after.slice(0, paramEnd) : after).trim();
        if (params.includes("+") || params.includes("${") || params.includes("`")) {
          dynamic = true;
          raw = params.slice(0, 300);
          remarkExtra = "拼接表达式候选";
        }
      }
      if (!raw) continue;
      const cls = classify(raw);
      const isDynamic = cls.dynamic || dynamic;
      const snippet = content.slice(Math.max(0, m.index - 40), m.index + m[0].length + 60).replace(/\s+/g, " ").trim();
      results.push({
        entry_name: null,
        source_file: rel,
        line: lineOf(content, m.index),
        code_snippet: snippet.slice(0, 200),
        raw_target_url: raw.slice(0, 300),
        entry_type: type,
        is_hardcode_url: !isDynamic && cls.kind === "internal",
        dynamic: isDynamic,
        external: cls.external,
        kind: cls.kind,
        remark: remarkExtra || (isDynamic ? "动态拼接候选" : cls.kind === "internal" ? "静态候选" : cls.kind),
      });
    }
  }
}

function main() {
  const args = process.argv.slice(2);
  const root = path.resolve(args[0] || ".");
  const outIdx = args.indexOf("--out");
  const outPath = outIdx >= 0 ? path.resolve(args[outIdx + 1]) : path.join(root, "route_manage", "01_raw_scan_routes.json");

  const files = [];
  walk(root, files);
  const results = [];
  for (const f of files) scanFile(f, root, results);

  const byType = {};
  let hard = 0, dyn = 0, ext = 0, internal = 0;
  for (const r of results) {
    byType[r.entry_type] = (byType[r.entry_type] || 0) + 1;
    if (r.is_hardcode_url) hard++;
    if (r.dynamic) dyn++;
    if (r.external) ext++;
    if (!r.external && r.kind !== "special" && r.kind !== "empty") internal++;
  }

  const summary = {
    scanned_files: files.length,
    total_candidates: results.length,
    by_type: byType,
    hardcoded_internal: hard,
    dynamic_candidates: dyn,
    external_links: ext,
    internal_candidates: internal,
    scan_time: new Date().toISOString(),
    note: "粗扫候选清单：机器提取，语义审计由 Agent 完成；硬编码内部URL需人工复核确认",
  };

  fs.mkdirSync(path.dirname(outPath), { recursive: true });
  fs.writeFileSync(outPath, JSON.stringify({ summary, routes: results }, null, 2));
  console.log(JSON.stringify(summary, null, 2));
  console.log("OUTPUT:", outPath);
}

main();
```
