# 四阶段工作流详解

> 配套主 SKILL.md 的四阶段展开。每个阶段的输入、动作、产出、判定标准。

## 阶段1 · 体检（扫描）

**输入**：项目路径 + 范围（full/code/interaction/automation）

**动作**：三视角并行，各自独立产出清单，互不共享上下文：
- 代码层扫描员 → `scan-checklist.md` 驱动，纯静态 grep/read
- 交互层走查员 → `sop-6dimensions.md` 驱动，Playwright 真实走查
- 自动化巡检员 → `scripts/smoke-template.js` 起手，逐页断言

**产出**：《问题清单》三份（按 report-template.md 格式）
**判定**：每个发现必须有实证（grep 结果 / 代码片段 / 运行时错误），禁止臆测。

### 交叉验证技巧
- 同一生辰在 snapshot/hub/report 多处对比结论 → 抓"算法口径不一"
- 同一操作在多个页面执行 → 抓"行为不一致"
- 静态看源码 + 运行时触发隐性分支 → 抓"肉眼正常但逻辑错"

## 阶段2 · 分级

**输入**：三份清单
**动作**：
1. 去重合并（三份清单常有重叠项）
2. 标注等级：P0 红线 / P1 一般 / P2 建议
3. 按主题归批（正确性/链路/安全/状态/清理）
**产出**：统一问题清单 + 分批方案表
**判定**：P0 必须全修；P1/P2 允许 修/删/留 三选一（人类决策）

## 阶段3 · 分批修复

**每批流程**（4-7 项）：
```
1. 方案：改哪些文件、为什么、风险
2. 人类确认/驳回（只确认，不描述技术细节）
3. 修复（最小修改，不动未授权文件）
4. 该批回归：Playwright 用例（现象已修的断言）
5. 全站冒烟：scripts/smoke-template.js 0 报错
6. 通过 → 进下一批；失败 → 修复后复验
```

**批主题参考**：
- 批次1 数据正确性（最优先，影响信任）
- 批次2 导航与跳转链路
- 批次3 边界与安全
- 批次4 状态与反馈
- 批次5 工程清理（删死代码/收敛样式/清注释）

**注意**：批次顺序按影响面排，正确性 > 可用性 > 安全 > 体验 > 整洁。

## 阶段4 · 回归校验

**动作**：
1. 全站冒烟 0 pageerror / 0 console.error / 关键资源 0 失败
2. visual-verify skill：对关键页面截图 + vision 检查渲染
3. 对照问题清单逐项确认已修、无新引入
**产出**：治理总结（各批明细 + 遗留项 + 文档索引）
**判定**：红线清零即达标；遗留项必须明确写"为什么留/何时处理"
