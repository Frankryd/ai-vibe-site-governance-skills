# 代码层扫描检查清单（静态）

> Agent 拿这份清单对源码做只读扫描，逐项排查。每项给具体 grep/命令思路。全部只读，禁止改代码。

## 1. 死代码
| 检查 | 方法 | 判定 |
|------|------|------|
| 死函数 | `grep -rn "函数名" --include='*.js' .` 去掉定义行/注释 | 引用数=0 → 死函数 |
| 死文件 | 对每个 js 文件 `grep -rl "文件名" --include='*.html' .` | 0 页面引入 → 死文件 |
| 死页面 | 全站 href 是否有指向该页 | 无任何链接 → 死页面 |
| 死依赖 | 引入的 CDN/库有无 `new X()` 调用 | 引入但 0 调用 → 死依赖 |

## 2. 重复/冲突实现
| 检查 | 方法 | 判定 |
|------|------|------|
| 同一算法多份实现 | grep 关键常量/函数名（如权重 `0.6`）跨文件 | 多处独立实现 → 口径不一风险 |
| 同 class 多处定义 | grep 选择器跨 css 文件 | 重复定义 → 覆盖顺序靠运气 |

## 3. schema 漂移（localStorage / 配置）
| 检查 | 方法 | 判定 |
|------|------|------|
| 同一 key 多种写结构 | grep `setItem('key'` 各处字段集合 | 字段不一致 → 漂移 |
| 消费方字段缺失 | 读方用的字段在写方是否存在 | 读方依赖不存在字段 → 数据丢失/误判 |

## 4. 安全向量
| 检查 | 方法 | 判定 |
|------|------|------|
| 用户输入拼 innerHTML | grep `innerHTML.*+.*input|city|name|email` | 未转义 → XSS 向量 |
| 敏感信息打印 | grep `console.log` 里是否含 email/params | 打 PII → 隐私风险 |
| 硬编码密钥 | grep `sk-|key=|token=|AKIA|ghp_|AIza` | 存在 → 泄露 |
| .env 被忽略 | 检查 .gitignore 是否含 .env | 未忽略 → 提交风险 |

## 5. 空 catch / 静默失败
| 检查 | 方法 | 判定 |
|------|------|------|
| 空 catch | `grep -rnE "catch\s*\(\s*\w*\s*\)\s*\{\s*\}"` | 吞错 → 保存失败也当成功 |
| 校验后置 | 检查函数内校验 vs 业务计算顺序 | 校验在计算后 → NaN 先抛 |

## 6. 残留/过时
| 检查 | 方法 | 判定 |
|------|------|------|
| 过时注释 | grep 引用了已删除文件/行号 | 存在 → 误导排障 |
| SPA 残留 | grep `go('`/路由函数 | 定义仅个别页 → 地雷 |
| 幽灵字段 | grep 写入了但从无读取 | 存在 → 无人消费 |

## 7. 全局污染
| 检查 | 方法 | 判定 |
|------|------|------|
| 顶层 var/function | 无 IIFE 包裹的全局量 | 命名撞车风险 |
| 同名函数多处 | 同一函数名不同文件 | 加载顺序决定谁赢 |

## 8. 硬编码魔法值
| 检查 | 方法 | 判定 |
|------|------|------|
| 价格/权重/色值 | grep 数字/hex 色值多处出现 | 改一处需多文件同步 → 漂移 |

## 验证纪律
- 只读扫描（grep/read/ls），临时脚本放系统 /tmp，不写项目
- 每个发现附实证（grep 结果或代码片段）
- 区分：肉眼可见 bug / 隐性潜伏 bug（页面正常但逻辑错，按红线处理）
