# 8 个技术修复模式：AI-vibe 高频坑的通用解法

> 每个模式：坑 → 解法 → 为什么有效。全部在本项目实战验证过。

## 1. 单一算法出口（收敛多份实现）
- **坑**：同一领域算法被 AI 各页面各写一遍，口径不同 → 跨页结论打架（如"缺金" vs "缺水"）
- **解法**：抽公共函数做唯一入口，各页调用它，删自写副本
- **为什么有效**：AI 每轮各自"写对"，无人做跨页一致性校验；单一出口让口径强制统一
- **实证**：五行/用神 5 处实现收敛为 1 处，snapshot/hub/report/remedies 四页结论从此一致

## 2. Schema 单出口（写前归一化 + 读时兜底）
- **坑**：localStorage 同一 key 被多轮迭代写成不同结构，字段漂移 → 数据丢失/误判
- **解法**：所有写入走一个函数，写前补默认字段，读时逐字段兜底
- **为什么有效**：schema 无中央定义、无迁移、无读取兜底是病根；单出口让结构强制收敛
- **实证**：`mpNormalizeBirth` 修掉"已知时辰被静默丢弃""徽章英文取不到"

## 3. 全局安全垫片（消除残留函数地雷）
- **坑**：SPA 迁移多页后残留 `go('view')` 调用，仅个别页有定义 → 其余页一碰 ReferenceError
- **解法**：在共享脚本提供全局兜底实现（视图名→真实页面映射，未知回首页），永不抛错
- **为什么有效**：垫片让所有残留调用变安全，无需逐处删；同时堵住"巨型 try/catch 吞错假装正常"
- **实证**：全站统一 `go()`，20+ 处残留调用从此安全

## 4. 内存渲染 → 结果持久化
- **坑**：工具结果只存内存，刷新/回退即失，用户白算
- **解法**：渲染结果存 localStorage（纯展示 HTML + 必要输入），页面加载时恢复
- **为什么有效**：静态站无后端，localStorage 是唯一可靠持久层；恢复让回退体验连续
- **实证**：`mpSaveResult/mpRestoreResult`，四页刷新全部存活

## 5. 反馈通道自动兜底（toast 自动建节点）
- **坑**：AI 各页调 toast() 但多数页没挂 toast 节点 → 提示全被吞，用户零反馈
- **解法**：反馈函数发现无节点时自动创建（样式全局已有），一次修复全站
- **为什么有效**：反馈缺失比错误本身更伤体验；自动建节点让所有调用立即可见
- **实证**：7 个工具页的静默失败提示全部恢复可见

## 6. 安全基线：用户输入一律 escapeHtml
- **坑**：AI 把用户输入直接拼 innerHTML → 潜伏 XSS
- **解法**：所有用户输入进 HTML 前过 `escapeHtml()`，并验证载荷被中和
- **为什么有效**：AI 把用户文本当信任输入是通病；统一转义一劳永逸
- **实证**：`<img onerror>` 城市名注入被验证无法触发

## 7. 校验前置（边界检查先于业务逻辑）
- **坑**：AI 把校验写在业务计算之后 → NaN 先抛异常吞掉校验，静默失败
- **解法**：必填/合法性校验提到函数最前
- **为什么有效**：边界输入未处理 + 校验后置 = 双缺陷叠加；前置让校验必然执行
- **实证**：起名空提交从"静默失败+NaN 报错"变为 toast 提示

## 8. 数据驱动 UI 状态（替代逐页硬编码）
- **坑**：导航高亮、菜单项等状态逐页手写 → 漂移、漏改、跨页不一致
- **解法**：用一个共享 JS 按当前页面路由计算状态，覆盖硬编码
- **为什么有效**：逐页硬编码在 20+ 页面规模下必然失控；数据驱动单一事实源
- **实证**：导航高亮从"每日页高亮 Readings"修成自动归属 Explore

## 附：全局安全底线
- 用户输入 → HTML 前必须 escapeHtml
- 未配置的服务（分析/收款）→ 禁止输出 PII 到控制台
- 敏感信息 → 不硬编码，走环境变量/.env；.env 必须进 .gitignore
- 写入/改动/删除 → 先经人类确认
